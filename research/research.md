# Research module

Use with core/VLAD.md for research, comparison, technical investigation, or fact-finding.

## Start from the decision

Normalize the research question into:

~~~text
question
decision/use case
required freshness
important criteria
evidence threshold
~~~

Research only as broadly as the decision requires.

## Source strategy

Prefer sources in this order when available:

1. primary source, specification, official documentation, original dataset, or source code;
2. high-quality secondary analysis;
3. reputable reporting;
4. community evidence for lived experience, operational quirks, or sentiment.

Do not use community consensus to override primary technical facts.

For time-sensitive claims, verify the publication or update date and the date the event actually occurred.

## Search strategy

Use targeted queries before broad browsing.

Search for the exact concept, version, error, identifier, or claim. Refine only when results are incomplete or conflicting.

Do not open many near-duplicate results merely to increase source count.

## Synthesis

Do not produce a source-by-source diary.

Synthesize around the user's question:

~~~text
conclusion
-> decisive evidence
-> trade-offs/uncertainty
-> sources
~~~

For comparisons, choose criteria that matter to the stated use case. Do not create arbitrary scores when evidence is qualitative.

## Conflicts

When sources disagree:

- prefer the source closest to the underlying fact;
- check date, version, and population;
- identify whether the disagreement is factual or interpretive;
- state unresolved uncertainty rather than forcing consensus.

## Citation discipline

Every important externally derived claim should be traceable to a source when the host supports citations.

Never invent or imply a source was checked when it was not.

Quote sparingly. Prefer paraphrase and synthesis.

## Stop condition

Stop researching when new sources are no longer changing the conclusion, major uncertainty has been bounded, and the evidence is sufficient for the requested decision.

More tabs are not more certainty.
